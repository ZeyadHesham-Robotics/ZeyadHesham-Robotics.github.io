01 — Architecture

System Overview

The pipeline is a single Python module composed of 12 classes, each with a single responsibility. A VisionPipeline orchestrator instantiates and wires every component. Configs are loaded from JSON files at startup, so you can tune parameters without touching code.

05 — Smoothing

KalmanTracker

KalmanTracker
Constant-velocity Kalman filter on the 2-D pixel-space centre (cx, cy).
Math

Raw contour centres jump by several pixels frame-to-frame due to noise, lighting variation, and partial occlusion. The Kalman filter models the cube centre as moving at constant velocity, so its prediction resists outlier jumps while still tracking genuine motion.

State vector: [x, y, vx, vy] — position and velocity. Measurement vector: [x, y].

# State transition (dt = 1 frame) F = [[1, 0, dt, 0], [0, 1, 0, dt], [0, 0, 1, 0], [0, 0, 0, 1]] # Usage smooth_cx, smooth_cy = tracker.update(raw_cx, raw_cy)

Methods

update(cx, cy) → (float, float) — Predict + correct cycle. Returns the smoothed centre.

reset() — Call when detection is lost so the filter re-initialises on next detection.

Angle Normalisation

cv2.minAreaRect returns angles in (-90, 0]. For a square/cube, 90° rotations are equivalent, so the angle is collapsed to [0, 90):

if rw < rh: angle += 90 # align reference to long axis angle = angle % 90 # collapse cube's 90° symmetry → [0, 90)

Methods

detect(frame) → DetectionResult | None — Single detection pass. Returns None if no blob or blob is too small.

detect_with_mask(frame) → (result, mask) — Same, but also returns the binary mask for the debug window.

build_mask(frame) → np.ndarray — Exposed separately so you can inspect or test the mask independently.

07 — Geometry

CoordinateTransformer

CoordinateTransformer
Implements the full pixel → camera 3-D → robot base coordinate chain.
Math

Step 1 — Depth from Apparent Size

The cube's known physical size and measured pixel footprint let us recover depth using the pinhole model:

Z = (fx × cube_size_m) / pixel_size # metres X = (cx_px - cx0) × Z / fx Y = (cy_px - cy0) × Z / fy

Step 2 — Camera → Robot Base Frame

A simple translation + axis flip (camera Y is flipped w.r.t. robot Y, depth becomes negative Z offset):

robot_x = cam_offset_x + X_cam_mm robot_y = cam_offset_y - Y_cam_mm # Y-axis inversion robot_z = cam_offset_z - Z_cam_mm # depth inversion

Step 3 — Workspace check

Sets result.in_workspace = True only when the robot X and Y are inside the configured safety bounds.

E6POS Serialisation

to_e6pos(result) → str — Formats a KUKA E6POS string:

"{X 653.40, Y 12.80, Z 247.10, A 180.00, B 0.00, C 37.50}"
✓ The C field in E6POS carries the in-plane rotation angle of the cube — allowing the robot gripper to align with the cube's face before grasping.
08 — Safety Gate

StabilityGuard

StabilityGuard
Prevents the robot from chasing every flicker — only fires after N consecutive stable frames.
Logic

A detected pose is considered stable when the robot-frame position has not changed by more than threshold_mm (default 5 mm) for at least required_frames (default 5) consecutive frames.

# In VisionPipeline.run(): if guard.is_stable(result): bridge.send(e6pos) # only now — cube has settled
⚠ Call guard.reset() whenever CubeDetector returns None, so the counter starts fresh on the next detection.
09 — I/O

RobotBridge

RobotBridge
TCP socket sender. Set enabled=False for dry-run / simulation mode.
I/O

Opens a fresh TCP connection per message (stateless). The KUKA controller must be running a KRL socket server or RSI listener at the configured IP:port.

bridge = RobotBridge(ip="192.168.1.100", port=30000, enabled=False) bridge.send(e6pos) # prints [DRY-RUN] when enabled=False

send(message) → bool — Returns True on success, False on TCP error. Always wraps in try/except with a 2-second timeout.

09 — I/O

DetectionLogger

DetectionLogger
Appends every stable detection to a CSV file for offline drift analysis.
I/O

CSV columns: timestamp, x_robot_mm, y_robot_mm, z_robot_mm, angle_deg, pixel_size, area.

The file is opened in append mode ("a"), so runs accumulate without overwriting previous data. The header row is written only if the file is empty.

Use the log to spot systematic drift across sessions, evaluate calibration accuracy, or build a dataset for further improvements.

11 — Calibration

HSVTuner

HSVTuner
Run-once interactive window for calibrating orange detection thresholds under your lighting.
UI

Opens a trackbar window displaying the live masked image. Adjust the 6 sliders (H/S/V min and max) until only the orange cube is visible in the mask. Press S to save to JSON, Q to quit.

# Uncomment in __main__ to run before the pipeline: HSVTuner(cam_cfg.index, cam_cfg.backend, "color_config.json").run()
✓ Re-run the tuner any time you change lighting conditions or move to a different environment. The saved JSON is loaded automatically on next startup.

13 — Orchestrator

VisionPipeline

VisionPipeline
Top-level class. Instantiates all components and runs the main capture loop.
Orchestrator

Main loop logic

while True: ret, frame = cap.read() result, mask = detector.detect_with_mask(frame) if result: result.cx_px, result.cy_px = tracker.update(...) # smooth result = transformer.transform(result) # 3-D coords if result.in_workspace: e6pos = transformer.to_e6pos(result) stable = guard.is_stable(result) if stable: bridge.send(e6pos) # TCP to KUKA logger.log(result) # CSV append else: tracker.reset() guard.reset() vis = renderer.draw(frame, result, stable, e6pos) cv2.imshow("Vision → KUKA", vis)
ℹ The loop is wrapped in a try / finally block, so the camera is always released and all windows are destroyed even if an exception occurs.
14 — Usage

Quick Start

1. Calibrate your camera

Replace fx=800, fy=800 in CameraConfig with values from cv2.calibrateCamera() using a chessboard. Save to camera_config.json.

2. Tune your HSV thresholds

# Uncomment in __main__: HSVTuner(cam_cfg.index, cam_cfg.backend, "color_config.json").run()

3. Measure your camera offset

Physically measure the distance from the camera lens to the robot base origin and set cam_offset_x/y/z in RobotConfig. Save to robot_config.json.

4. Run in dry-run mode

pipeline = VisionPipeline( cam_cfg = CameraConfig.from_json("camera_config.json"), robot_cfg = RobotConfig.from_json("robot_config.json"), color_cfg = ColorConfig.from_json("color_config.json"), log_path = "detections.csv", send_robot=False, # ← safe: prints [DRY-RUN] only ) pipeline.run()

5. Enable robot transmission

Once the dry-run output looks correct, flip send_robot=True. Verify your workspace limits are conservative before doing so.
